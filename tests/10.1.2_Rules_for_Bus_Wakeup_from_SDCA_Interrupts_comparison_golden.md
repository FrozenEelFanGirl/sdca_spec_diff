### Rules for Bus Wakeup from SDCA Interrupts

> **Mapped from comparison §9.1.2**
>

1. Per **[MIPI05],** a SoundWire **Family** Peripheral generates a **Wake** **request** only when the Peripheral state changes from Attached_OK **/ Attached** to Alert. If further interrupts occur that cause the Peripheral to remain in the Alert state, then the Host should handle all of these conditions and check that the **Peripheral** has **exited** **the** **Alert** **state** before considering the response to the Alert state to have been completed.
2. When the Manager has stopped the clock, an SDCA Peripheral Device may use either of the following policies for when to generate a Wake request:
    1. Whenever its state is Alert (i.e., there is at least one **interrupt** that **is both asserted and enabled; e.g., for SoundWire Classic, IntStat bit N** is a 1 and **IntMask** **bit** **N** is also 1).
    2. Under the same conditions under which it would generate a PREQ **/ LC_Request** at the start of a Frame (i.e., when it has not received a Ping Command since its state last **entered** Alert, see **[MIPI05]).**
