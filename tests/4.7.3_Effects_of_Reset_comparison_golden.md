### Effects of Reset

> **Mapped from comparison §4.7.4**
>

SDCA_Reset changes most Controls to a known state **(which** **is** **discoverable** from DisCo data), including changing Power State Controls in the Power Domain Entities (PDE).

#### Effect of Reset on Function_Status Control

> **Mapped from comparison §4.7.3**
>

> **v1.0:**
> ### Resets in Function_Status Control
>
Each Function has a Function_Status Control (see [Section 7.14.1 — Function_Status (Function-Level)](../sections/7.14.1_Function_Status_Function-Level.md)) that reports to software whether various events such as reset have happened asynchronously, i.e., not as a direct result of software writing to Controls. **In this Control, the Function_Has_Been_Reset bit is set by the Device Function when a reset event occurs. Reset might also result in other status bits being set depending on the Device state prior to reset per [Table 257 — Effect of Resets on RW1C Bits in a Function_Status Control](../tables/Table257_v1p2r17.md).**

> **v1.0:**
> Each Function has a Function_Status Control (see [Section 7.14.1 — Function_Status (Function-Level)](../sections/7.14.1_Function_Status_Function-Level.md)) that reports to software whether various events such as reset have happened asynchronously, i.e., not as a direct result of software writing to Controls.
>
#### Effects of Reset on Memories

SDCA_Reset does not have any explicit effect on the content of memories. However, the content of memories might be lost due to the Effective Power State of an Entity changing to PS3, which is a consequence of SDCA_Reset.

> **v1.0:**
> *Unchanged.*
